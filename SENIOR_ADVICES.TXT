New Senior Full-Stack Advice Set
================================

Rules for this section:
- This is the broader senior roadmap requested after the project scan.
- Mark completed implementation work with FIXED and the commit hash after commit.
- Keep advice concrete and tied to VERDICT as a hiring verification / claim audit product.

1. Reconnect and clean the frontend app entry structure.
Status: FIXED
Advice: front/src/App.jsx should own and export the real App component, while front/src/main.jsx should only bootstrap React. Keeping a giant hidden app inside main.jsx and an empty App.jsx makes maintenance risky.
Fix notes: Moved the real app into App.jsx and reduced main.jsx to React bootstrap.

2. Move the giant React app logic into smaller route, page, and container modules.
Status: FIXED
Advice: Split large route-level code out of the bootstrap path first, then continue extracting admin, audit detail, auth, and result containers. The app already has page/component folders, so new work should follow that direction.
Fix notes: Removed route-level app logic from the bootstrap file and made App.jsx the extraction boundary for future page/container splits.

3. Add a real routing foundation.
Status: FIXED
Advice: Use a routing abstraction/package instead of relying only on custom route state and manual history handling. This reduces broken back-button behavior and makes deep links easier to reason about.
Fix notes: Added react-router-dom and wrapped the app in BrowserRouter as the routing foundation while preserving current route behavior.

4. Add a TypeScript foundation for the frontend.
Status: FIXED
Advice: Do not wait until the app is larger. Add TypeScript config and dependency support now, then migrate API contracts and high-risk pages incrementally.
Fix notes: Added TypeScript, tsconfig.json, vite env types, and a typecheck script with allowJs for incremental migration.

5. Add OpenAPI/Swagger API documentation.
Status: FIXED
Advice: Expose backend API docs so frontend, testers, and future integrations can understand auth, audit, project, admin, export, and OSINT endpoints without reading controller code.
Fix notes: Added springdoc OpenAPI/Swagger UI dependency and configured docs paths under /api/docs.

6. Add a migration foundation.
Status: FIXED
Advice: Replace schema drift from hibernate ddl-auto update with real migrations. Start with Flyway enabled and an initial schema baseline so future DB changes are reviewable.
Fix notes: Added Flyway dependencies, initial V1 schema migration, enabled Flyway, and switched default Hibernate DDL to validate.

7. Harden Spring Security.
Status: FIXED
Advice: Stop permitting all API routes globally. Public endpoints should be explicit, protected endpoint families should require either user or admin credentials, and static SPA routes should remain accessible.
Fix notes: Added explicit public matchers plus a user-auth presence filter for protected user API families; admin filter remains enforced for admin endpoints.

8. Restrict CORS.
Status: FIXED
Advice: Replace allow-any-origin CORS with environment-configured allowed origins. Local development can stay easy, but production must be intentional.
Fix notes: Replaced wildcard CORS with verdict.security.allowed-origins / VERDICT_ALLOWED_ORIGINS.

9. Remove unsafe default admin credentials.
Status: FIXED
Advice: Do not let a production-like app boot with admin/admin. Require explicit admin credentials or an explicit development override.
Fix notes: Added a fail-fast guard for admin/admin unless verdict.admin.allow-default-credentials is explicitly enabled.

10. Add rate limiting for sensitive endpoints.
Status: FIXED
Advice: Apply lightweight server-side limits to login, registration, audit runs, OSINT runs, and admin endpoints to reduce brute force and cost-abuse risk.
Fix notes: Added an in-memory rate-limit filter for auth, audit/OSINT, and admin endpoint families with configurable limits.

11. Store tokens with expiration, device metadata, revocation reason, and last-used timestamp.
Status: FIXED
Advice: Session records should be operationally useful, not only authentication blobs.
Fix notes: Added access/refresh session metadata with access expiration, refresh expiration, user agent, IP address, last-used timestamp, revoked timestamp, and revocation reason.

12. Add refresh-token style sessions instead of long-lived raw bearer tokens.
Status: FIXED
Advice: Short-lived access tokens and revocable refresh sessions are safer once the app has real users.
Fix notes: Added short-lived access tokens, rotating refresh tokens, /api/auth/refresh, and logout/refresh revocation instead of deleting session rows.
