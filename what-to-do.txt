P0 — CRITICAL: ROUTE STABILITY, PERMISSIONS, & MESSAGING
================================================================================

1. Make app routes impossible to break into the Recovery screen
   Why: The user already hit "VERDICT hit a display problem." If the app
        crashes, every feature feels untrustworthy.
   Do this:
   - Route-level error boundaries with fallback actions (Back to dashboard,
     Reload data, Logout).
   - Guard all code that assumes project/user/message data exists before
     async loading finishes.
   - Make empty, loading, forbidden, and not-found states explicit for
     every route.
   - Add a manual smoke checklist (docs/smoke-checklist.md).

2. Fix blank route loading on direct navigation
   Why: Opening /audit, /projects, etc. shows a blank screen for a few
        seconds before content appears. This feels like a crash.
   Do this:
   - Add real loading skeletons for direct routes instead of blank screens.
   - Make the intro animation run only once, not block every route.
   - Add refresh/retry states for Messages, Projects, Admin, Audit history.

3. Make permissions server-authoritative (Team, Invite, Project)
   Why: Team page has frontend permission atoms, but backend leans on
        project owner checks. This can cause invited users, owners, and
        team views to disagree.
   Do this:
   - Define one backend permission model: Viewer, Voter, Reviewer, Screener,
     Coordinator, Admin, Head Admin, Custom.
   - Persist custom permissions instead of localStorage overrides.
   - Add canInvite and canTeamManage on the backend.
   - Return myPermissions and myRole from project/member APIs.
   - Make accepted invite membership visible to both accounts immediately.
   - Add backend tests for all permission flows.

4. Stabilize message delivery and message state
   Why: If sent/received/read/star/reply/forward state differs between
        accounts, users will not trust the product.
   Do this:
   - Make server messages the source of truth; local fallback only for
     logged-out demo mode.
   - Add backend replyToMessageId, forwardedFromMessageId, readAt,
     starred, archived, and candidate attachments support.
   - Log message events (sender, receiver, title, body summary, timestamp).
   - Add visible delivery states: sending, sent, failed, retry.
   - Verify both accounts see same inbox/sent/team state after refresh.

5. Lock the core hiring workflow end to end
   Why: VERDICT is valuable only if a team can create a job, add candidates,
        review them, discuss them, and make a decision without confusion.
   Do this:
   - Persist candidate votes, score out of 5, star, downvote, notes, and
     status changes on the backend.
   - Add candidate lifecycle statuses: Unreviewed, OnCheck, OnInterview,
     Hired, Closed (as specified in front/newstufftodo).
   - Gate each status transition by backend permission.
   - Add per-candidate activity history (viewed, note added, vote changed,
     status changed, message sent).

6. Fix admin password field (plain text on /admin)
   Why: Currently type="text" instead of type="password".
   Do this:
   - Change the admin login password input to type="password".

================================================================================
DEFINITION OF DONE
================================================================================

- Works after browser refresh.
- Works from both owner and invited member accounts.
- Backend rejects forbidden actions even if frontend is bypassed.
- Empty/loading/error states are visible and polished.
- Mobile layout does not overlap or clip.
- Important actions create an audit/activity/log entry.
- Feature has at least backend test coverage for permission/data rules.
- The UI looks professional enough for a live demo.
- All screens share the same visual language (no mismatched components).
