1.
Keep OSINT/osints.txt as a registry/list, not tool source code.
2.
Install tools outside the app, for example:
◦
C:\OSINT\tools
◦
or Python venvs under C:\OSINT\venvs
3.
Your Java/React app should call one controlled wrapper script/API, not directly run 20 tools.
4.
Start with 3 tools only:
◦
Maigret or Sherlock for usernames
◦
Holehe for email footprint
◦
GitHub API/CLI for repos/languages
5.
Save results as JSON, then your backend reads that JSON and shows it in SignalTrace.
Recommended OSINT/osints.txt format:
# tool | purpose | install | output | enabled
maigret | username search | pipx install maigret | json | yes
holehe | email footprint | pipx install holehe | text/json-wrapper | yes
github-api | repo/language evidence | no install, use API | json | yes
sherlock | username search backup | pipx install sherlock-project | text/json-wrapper | later
spiderfoot | broad OSINT automation | docker or pip | json/csv | later
For now, put the tools you are considering into that file. Then I can turn it into a clean install plan and generate a wrapper like tools/osint_runner.py that runs only enabled tools and outputs one normalized JSON report for the Java backend.
